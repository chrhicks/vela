# rig-model

Checks and offline tools for the rig model packages (`@vela/rig-*`, see [docs/rig-model.md](../../docs/rig-model.md)). They run on a development machine and never touch a rig or Cria.

Needs Node 26: the scripts here are TypeScript that Node runs directly.

| Command | What it proves |
| --- | --- |
| `pnpm check` | lint, `rig-model:guards`, `rig-model:no-real-site`, build and tests, in that order. The rig model packages are part of the repository's one check. |
| `pnpm lint` | oxlint with the rig model's import rules in `.oxlintrc.json`. |
| `pnpm rig-model:guards` | each rule bites. `guards/fixtures/bad/<case>` holds one deliberately bad file per rule and an `EXPECT` file naming the diagnostic. `fixtures/good` holds files that must pass. A rule that stops biting fails here. It also proves the `no-real-site` behaviour below. |
| `pnpm test` | vitest. |
| `pnpm rig-model:resolve-trial` | re-solves the three baseline frames of alignment trial `2bfbf00c` (2026-10-26) with ASTAP and compares each with the solve Vela recorded for it. It also checks each file against the sha256 the trial recorded, so it is the same pixels. ASTAP and its catalogue are read from `~/.local/share/vela/astap`; the trial from `~/.local/share/vela/alignment-diagnostics/trials`. It prints separations and timings, never coordinates, and exits 1 if any centre is more than `--tolerance-arcsec` (default 2) from the recorded one. |
| `pnpm rig-model:decode-journals` | decodes every line of Vela's two Cria journal files in `~/.local/share/vela/traces/` (or the paths you pass) with `@vela/rig-events`. It prints a count per kind and exits 1 on any failure. It reads the files and writes nothing. The live file grows, so its counts rise between runs. Takes about two minutes. |
| `pnpm rig-model:frame-sources` | reads Vela's data folder (`--data DIR`, else `VELA_DATA_DIR`, else `~/.local/share/vela`) with `@vela/rig-frames`: finds every saved image, joins it to its frame record by `image.id`, and lists alignment trials per night. It prints counts, run ids and times, never a coordinate, and writes nothing. It exits 1 when an image captured after the first frame record has no record, a record of a saved image has no image, a joined pair disagrees, or a source cannot be read. Images captured before the first record (2026-10-19) are counted apart. `--through-night 2026-10-26` limits the table to the nights up to then; `--utc-offset-minutes N` sets the site's offset for the night boundary (default 0). Takes about a second. |
| `pnpm --filter @vela/rig-model-tools indi-parity -- --recordings DIR` | imports a folder of Cria INDI recordings (one folder per Cria run, with `manifest.json` and `traffic.jsonl`) with `@vela/rig-events` and compares the mount states with the ones Vela's Cria log gives (`--journal FILE|DIR`, a run-log directory or an old journal file, default the 2026-10-15 to 2026-10-25 file in `~/.local/share/vela/traces/`). The window is `--from` and `--to` (ISO times, default 2026-10-24T00:00:00Z to 2026-10-25T12:00:00Z). Each journal state is compared with the latest recording state at or before it, in the same Cria run and inside the recording's time span. It prints how many states were compared, how many of them were slewing, the largest RA and Dec difference in display steps (from the `format` the driver defined), and any flag that disagrees (slewing, tracking, parked, pier side, frame, connected). It exits 1 if any difference is over one step or any flag disagrees. It prints no coordinates and writes nothing. The recordings are not in the repository, so it runs locally and not in CI. Takes about two minutes. |
| `pnpm rig-model:am5-profile -- --recordings DIR` | measures how the real AM5 behaves from a folder of Cria INDI recordings (the layout `indi-parity` reads). For each motion kind and rate (goto, home, rate moves at 8x and 9x, aborts) it takes stop latency, overshoot, landing offset, coast after Idle and speed, and prints count, median, p90 and max, marks any row with fewer than 5 samples, and lists every motion it skipped and why. `--report FILE.md` writes the report (else it prints), `--json FILE.json` writes the numbers per motion. It prints offsets and times only: no site, no RA or Dec. The recordings are not in the repository, so it runs locally and not in CI. Takes about 15 seconds. |
| `pnpm rig-model:backfill -- --out DIR --recordings DIR` | the first proof that the rig model sees real events. It solves every saved light frame with the real ASTAP binary, joins each to where the mount pointed at the exposure midpoint (`capturedAt + exposureSeconds * 500` ms) by running the night through the pure model, and reports three separate quantities per frame and per night: **alignment evidence** (what Vela's alignment trials measured), **pointing residual** (sky minus mount, east and north in arcminutes) and **drift** (the residual's slope across a run of back-to-back exposures). A night's finding holds each run's drift against the last alignment reading: a drift that needs more polar error than that, by more than 20 arcmin, disagrees with the alignment. The bracket runs from the alignment to the end of the shortest stretch from the start of that run that disagrees on its own (a slope is an average, so a change inside a run cannot be placed before it). The drift also fits a tracking-rate error, flexure or refraction, so the event night passes only when a later alignment reading is as large as the drift needs, and even then the report brackets the change by the alignment readings alone (up to that later reading) as well as by the drift. The bracket is *incomplete* while Cria was told to take exposures inside it whose pixels were not kept (counted from the recordings' `CCD_EXPOSURE` commands). Each solve is cached in `DIR/solves/<sha256 of the file>.json`, so a rerun solves nothing again. It writes `DIR/frames.jsonl` and the markdown report (`--report FILE`, else `DIR/report.md`), with no site and no coordinates. Options: `--data`, `--journal FILE|DIR` (repeat, oldest first; default the two Cria journals and the run log directory `$VELA_RUN_LOG_DIR` or `<data>/run-log`, used for a night no recording overlaps; old journals are rebuilt from their cells, run-log lines are read as they are), `--utc-offset-minutes N` (names the nights; default 0), `--from-night` and `--through-night DATE`, `--event-night DATE` and `--control-night DATE` (the event must show a change, the control must not), `--astap`, `--catalog`, `--field-height-degrees`, `--jobs`, `--timeout-ms`. Exit 0 complete, 1 failed, 2 bad arguments, 3 incomplete. It needs the real ASTAP and the saved images, so it runs locally and not in CI. Solving a night takes minutes; run it with `tools/runner/runner.py`. |
| `pnpm --filter @vela/rig-model-tools corpus -- --utc-offset-minutes N --audit-until INSTANT` | writes the inventory of frames the solve verdict (plan step 5's successor, step 6) is tested against: every alignment-trial frame, every saved light, and the audit's own synthetic frames as entries (`audit:*`). Each entry has its pixels (path and sha256) or the reason they are missing, the audit case ids it serves, the solve Vela journalled and the real ASTAP's solve of the pixels. Every audit case `PS-001` to `PS-038` is either a case in `corpus-inventory.ts` (with a `found`, `partial` or `missing` status) or listed there with the reason it has no frame. The audit kept one synthetic frame; copy it, or any later one, into `DIR/synthetic/` under the file name in the `specimens` table to give its entry pixels. It reads solves from step 4's cache (`--backfill DIR`, default `/mnt/storage/rig/backfill`, never written) and solves the alignment frames that kept their pixels itself, caching them in `--out DIR/solves`. A few-star frame (PS-008) is one ASTAP finds at most 210 stars in, counted from its `-log`. Writes `DIR/corpus.json` (default `/mnt/storage/rig/corpus`) and the markdown summary (`--report FILE`, else `DIR/report.md`): entries per source and case, each audit case's status, the median plate scale and the mirrored frames. `--audit-until` is the instant the audit stopped reading trials, for the row that compares with its 916 frames. The summary names frames by entry id and night and prints no coordinates. It needs the real ASTAP and the saved images, so it runs locally and not in CI. Takes about a minute once step 4's cache exists. |
| `pnpm --filter @vela/rig-model-tools solve-verdict -- --report FILE.md` | runs `judgeSolve` from `@vela/rig-astap` for each purpose on the solve corpus (`--corpus FILE`, default `/mnt/storage/rig/corpus/corpus.json`): the alignment solves Vela recorded up to `--audit-until` (default 2026-11-01T02:00:00Z), the same trials re-solved with their star counts, and step 4's saved lights. It prints accepted and rejected counts per purpose with the reasons, the margin of the worst good frame to each limit, and the verdict on the false solve of trial `eeef34da`. The expected scale comes from the corpus's configured field height and the frame height; `--parity` is the rig's CD determinant sign (default 1). Exit 0 when the false solve is rejected and every other frame of the audit set is accepted for alignment, 1 otherwise. It prints no coordinates. The corpus is not in the repository, so it runs locally and not in CI. |
| `pnpm rig-model:no-real-site` | no tracked or untracked text file holds a value from the forbidden list. Binary files and files over 8 MiB are not scanned, and the check names each one it skipped. Add `-- --history` to scan git history too. |

Pass options to a tool after `--`, for example `pnpm rig-model:resolve-trial -- --tolerance-arcsec 1`.

## no-real-site

Vela is public, and the real observing site must not appear in it. Tests use a synthetic site. The check reads forbidden values from `~/.config/rig/forbidden-values.txt` (one per line, mode 600, never committed) or from the file named by `RIG_FORBIDDEN_VALUES` or `--forbidden`. Its report names the file, the line and the entry number, never the value.

The list lives outside the repository, so a CI runner does not have it:

- **Locally**, a missing or empty list fails the check (exit 2). A check that cannot look proves nothing.
- **In CI** (`CI` set and not `0` or `false`), a missing list at the default path skips the check with a message and exit 0. An empty list, or a list you named that is missing, still fails.

`pnpm check` therefore runs the scan on Chris's machines and passes through on a runner. The guards prove all three behaviours.

Alignment trial journals hold the site in `evidence.physical.site`. Never commit or print them.
